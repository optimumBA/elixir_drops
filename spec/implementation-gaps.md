# Differences from the inspected implementation

Baseline inspection: `04ffe01a997e4e10c0c151c062b43c336ccae963`, 9 October 2026.
These are static-source findings and scope limits, not production exploit tests,
accepted backlog or authorization to change the application. Source is linked below;
reproduce each difference with an implementation test before claiming it repaired.

| ID  | Difference / evidence                                                                                                                                                                                                                                                                                                                                                                           | Specification treatment                                                                                                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G01 | [Show handlers](../lib/elixir_drops_web/live/drop_live/show.ex) delete/edit a supplied comment without checking current actor ownership; [form component](../lib/elixir_drops_web/live/comment/form_component.ex) retrieves supplied IDs. [Comment controls](../lib/elixir_drops_web/live/comment_components.ex) only show edit/delete to the author.                                           | Baseline access intent: `authorizedWrites`, `ownershipTest` and domain C02 enforce the server boundary. App implementation is not claimed conformant.                                                       |
| G02 | [Comments.verify_parent_comment](../lib/elixir_drops/comments.ex) checks root depth but not that parent and new comment belong to the same Drop.                                                                                                                                                                                                                                                | C01 / `crossDropParentTest` rejects cross-Drop parents.                                                                                                                                                     |
| G03 | [Drops filters](../lib/elixir_drops/drops.ex) paginate with strict timestamp/rank comparisons; [notification filters](../lib/elixir_drops/notifications.ex) use strict timestamp comparison. Equal timestamps/ranks can omit rows; standard latest query also lacks a tie-break.                                                                                                                | Proposed deterministic tie handling; discovery model includes tied relevance ranks and complete traversal. No specific SQL cursor representation is mandated. Notification cursor correction is prose only. |
| G04 | [Screenshot worker](../lib/elixir_drops/workers/screenshot_generator_worker.ex) loads a Drop snapshot, uses stable latest object names and persists uploads without comparing to newer code. Its failure path can clear a newer image.                                                                                                                                                          | Proposed fencing: `staleCompletionTest`; both storage and DB publication need protection, not just a status condition. Exact stale object writes remain outside the model.                                  |
| G05 | [Form screenshot selection](../lib/elixir_drops_web/live/user_drop_live/form_component.ex) labels unchanged code completed even if its old URLs/status are failed/pending.                                                                                                                                                                                                                      | Proposed preserve prior status without a successful image; `unchangedFailedCodeTest`.                                                                                                                       |
| G06 | [Search](../lib/elixir_drops/search.ex) deduplicates blank-prefix history but not matching-prefix history. [Search helper](../lib/elixir_drops_web/live/search_helper.ex) anonymous focus takes unsorted `list_popular_searches`; navbar/home/profile minimum-prefix paths differ.                                                                                                              | Proposed uniform dedup/ranking/trigger contract; `suggestionDedupTest` models valid normalized results. UI timing and case-sensitive history distinctions remain source-test obligations.                   |
| G07 | [MarkdownCache](../lib/elixir_drops/markdown_cache.ex) has local ETS invalidation. Generation can race invalidation; there is no cross-node cache invalidation. Keys use minute-resolution timestamps.                                                                                                                                                                                          | Delivery model is a single-node serialized cache abstraction; fresh-after-save is the target guarantee, not proof for concurrent or regional serving. No regional rollout is included.                      |
| G08 | [Snippet controller](../lib/elixir_drops_web/controllers/code_snippet_controller.ex) lacks explicit unknown-type validation; discovery also lacks an explicit modeled view-epoch fence. LiveView serializes much of the latter flow.                                                                                                                                                            | Proposed controlled invalid-type 400, and abstract stale-response isolation. `invalidSnippetTypeTest`/`stalePageTest` test models, not demonstrated source failures for every transport.                    |
| G09 | [Drop form](../lib/elixir_drops_web/live/user_drop_live/form_component.ex) ignores `Oban.insert` outcomes. [Sponsor handler](../lib/elixir_drops_web/live/drop_live/show.ex) consumes seen markers regardless of successful event insert.                                                                                                                                                       | Preserve partial-failure behavior: `enqueueFailureTest` and `dbFailureConsumesSeenTest`. No exactly-once or automatic recovery claim.                                                                       |
| G10 | [UserAuth](../lib/elixir_drops_web/user_auth.ex) resolves users at mount; [GitHub callback](../lib/elixir_drops_web/controllers/github_auth_controller.ex) clears tokens without proactively disconnecting all old sockets.                                                                                                                                                                     | Model command admission uses a currently valid token. Immediate expiry/revocation of already-mounted sockets is a proposed stronger boundary requiring an explicit implementation decision/test.            |
| G11 | [Show](../lib/elixir_drops_web/live/drop_live/show.ex) assigns nil then patches home while [template](../lib/elixir_drops_web/live/drop_live/show.html.heex) dereferences Drop fields. It updates total comment count on deletion but not root count. The [image worker](../lib/elixir_drops/workers/screenshot_generator_worker.ex) failure path does not consistently broadcast failed state. | Controlled failure and consistent displayed counts/states are baseline intent. Exact error-render and stale-control repairs remain implementation verification work, not Quint-proven behavior.             |

The suite intentionally does not silently copy these omissions into permissions or
safety rules. It also preserves genuine partial failures instead of inventing a
transactional outbox, durable PubSub or an eventual-delivery promise.
