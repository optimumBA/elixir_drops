# Screenshots

## Architecture

Each drop gets two screenshots — a social "meta" image and an "internal" card image — generated by headless Chrome (Wallaby) running inside a FLAME pool. Generation is offloaded from the request cycle via Oban. Images upload to S3-compatible storage (Tigris) and URLs are stored on the embedded `Drop.screenshot`. Progress is broadcast over PubSub so LiveView cards animate while the job runs.

Flow: `Drops.create_drop/2` (or update) enqueues `ScreenshotGeneratorWorker` -> worker calls `FLAME.call(ScreenshotGenerator, fn -> ... end)` -> Wallaby visits `/d/:id/code_snippet` at computed height -> captures PNG -> reads file -> `S3Helper.Client.upload_image/3` twice -> `Drops.update_drop/3` with completed URLs -> `Drops.broadcast_drop_screenshot_completion/4` at progress 100 -> enqueues `SitemapGeneratorWorker`.

## Screenshot Modules

| Module                                                | Purpose                                                              |
| ----------------------------------------------------- | -------------------------------------------------------------------- |
| `ElixirDrops.Workers.ScreenshotGeneratorWorker`       | Oban worker (queue `:seo_images`, max 5 attempts)                    |
| `ElixirDrops.Helpers.ScreenshotGeneratorWorkerHelper` | `calc_height/1` — computes Chrome window height from drop body       |
| `ElixirDrops.S3Helper.Client`                         | Behaviour + dispatcher (`:s3_helper` app env, defaults to `Http`)    |
| `ElixirDrops.S3Helper.Http`                           | Actual HTTP upload implementation                                    |
| `ElixirDrops.Workers.SitemapGeneratorWorker`          | Oban worker (queue `:seo_sitemap`, max 3 attempts) — per-drop + full |
| `ElixirDrops.Sitemap`                                 | Writes `priv/static/sitemap.xml`                                     |

## FLAME Pool

Configured in `ElixirDrops.Application`:

```
{FLAME.Pool,
 name: ElixirDrops.ScreenshotGenerator,
 idle_shutdown_after: 120_000,
 max_concurrency: 1, max: 1, min: 0}
```

Pool is gated by `parent:` clause — only starts on the parent node, not inside FLAME children. Uses Fly.io backend in prod.

## Upload Flow

- Filenames: `drop-meta-image-latest-#{drop.id}.png`, `drop-internal-image-latest-#{drop.id}.png`.
- `Drop.screenshot.status` transitions: `:skipped` (default) -> `:pending` -> `:completed` or `:failed`.
- Progress broadcasts: 50 (start), 60/65 (meta capture), 70/75 (internal capture), 80/85/90 (uploads), 100 (done).
- 1500ms sleep after upload before the 100 broadcast — works around Tigris serving delay.

## Wallaby Auth

Screenshot worker hits the app over HTTP with basic auth (`WALLABY_AUTH_USERNAME` / `WALLABY_AUTH_PASSWORD`) so the screenshot render route is not publicly callable. URL is rewritten to `scheme://user:pass@host/...` before `Browser.visit/2`.

## Oban Queues

| Queue          | Concurrency | Worker                      |
| -------------- | ----------- | --------------------------- |
| `:default`     | 10          | General jobs                |
| `:seo_images`  | 1           | `ScreenshotGeneratorWorker` |
| `:seo_sitemap` | 1           | `SitemapGeneratorWorker`    |

## Screenshots Pitfalls

- **Matching Chrome/ChromeDriver** — production images must pin matching versions for Wallaby to start sessions.
- **FLAME parent gating** — children marked `parent:` must not start inside FLAME workers; `Application.children/1` filters on `FLAME.Parent.get()`.
- **Screenshot failures set `:failed`** — the `with` fall-through calls `Drops.update_drop/3` to clear URLs before returning the error; don't rely on the job re-running to clean up.
- **Auth in URL must precede host** — `String.split(url, "//", parts: 2)` is intentional; changing it breaks the embedded credentials.
- **Tigris 1500ms sleep** — removing the `:timer.sleep(1500)` causes cards to render with 404s for a moment.
